# SDVX 자켓 공개 민감도 분류 기획

> 상태: 기획 기준 문서
> 범위: `char-gallery`의 SOUND VOLTEX 전체 자켓
> 목적: 향후 사이트 공개 시 자켓별 블러/숨김 등 검열 옵션에 사용할 일관된 메타데이터를 정의한다.

## 1. 핵심 원칙

`● / ○ / □ / ■`은 캐릭터의 나이, 성인 여부, 체형, 인기, 캐릭터 자체의 속성을 뜻하지 않는다.

분류 대상은 **각 자켓 이미지 자체**다.

- 캐릭터 단위로 일괄 분류하지 않는다.
- 곡 단위로 일괄 분류하지 않는다.
- 같은 곡이라도 난이도별 자켓 이미지가 다르면 각각 따로 분류한다.
- 같은 캐릭터도 자켓에 따라 서로 다른 등급을 가질 수 있다.
- `adultScore` 같은 선정성 숫자 점수는 사용하지 않는다.
- 인기순 정렬과 민감도 분류는 서로 독립된 데이터로 관리한다.

## 2. 분류 정의

### ● 강한 민감 이미지

**여성 캐릭터가 등장하는 자켓 중**, 공개 사이트에서 기본 블러 또는 강한 민감 이미지 처리를 고려할 수준.

판정 요소 예시:

- 노출이 매우 큰 경우
- 속옷 또는 이에 준하는 의상이 이미지의 핵심인 경우
- 특정 신체 부위를 구도의 중심으로 강하게 강조한 경우
- 포즈, 카메라 각도, 의상, 노출 등 여러 요소가 겹쳐 공개 민감도가 명확히 높은 경우

확실히 강한 민감 이미지라고 판단되는 경우에만 `●`을 사용한다.

### ○ 중간 민감 이미지

**여성 캐릭터가 등장하는 자켓 중**, 일반 이미지보다는 민감하지만 `●`까지는 아닌 수준.

판정 요소 예시:

- 수영복 등 노출도가 비교적 높은 의상
- 신체를 강조하는 구도가 일부 있는 경우
- 공개 환경에 따라 민감 이미지 옵션에 포함할 가치가 있는 경우

`●`과 `○` 사이가 애매하면 `○`로 둔다.

### □ 일반 여성 자켓

**여성 캐릭터가 등장하지만**, 별도의 민감 이미지 처리가 필요하지 않은 일반적인 자켓.

예시:

- 평범한 캐릭터 일러스트
- 일반적인 의상과 포즈
- 얼굴 또는 캐릭터 전체 중심의 구도
- 액션, 귀여움, 분위기 연출이 중심인 그림
- 일부 피부 노출이 있어도 이미지의 핵심이 선정적 연출이 아닌 경우

`○`과 `□` 사이가 애매하면 사이트 안전성 측면에서 `○`를 우선한다.

### ■ 비여성 자켓

`● / ○ / □`의 전제인 **여성 캐릭터가 등장하지 않는 자켓**.

예시:

- 남성 캐릭터만 등장
- 캐릭터 없음
- 로고/텍스트 중심
- 풍경/추상 그래픽
- 메카/동물/마스코트만 등장
- 기타 여성 캐릭터가 확인되지 않는 경우

남녀 캐릭터가 함께 등장하고 여성 캐릭터가 식별 가능하면 `■`로 보내지 않고 `● / ○ / □` 중 하나로 분류한다.

## 3. 판정 순서

각 자켓은 아래 순서로 판정한다.

1. 여성 캐릭터가 등장하는가?
   - 아니오 → `■`
   - 예 → 다음 단계
2. 강한 민감 이미지인가?
   - 예 → `●`
   - 아니오 → 다음 단계
3. 중간 민감 이미지인가?
   - 예 → `○`
   - 아니오 → `□`

여러 명이 등장하는 자켓은 **자켓 전체에서 가장 강한 민감 표현**을 기준으로 한다.

## 4. 난이도별 자켓 분류

분류 단위는 곡이 아니라 **실제 자켓 variant**다.

예:

```text
NOV  → □
ADV  → □
EXH  → ○
GRV  → ●
```

같은 곡이라도 자켓 이미지가 다르면 등급이 달라도 정상이다.

반대로 여러 난이도가 실제로 같은 이미지를 공유한다면 같은 판정을 재사용할 수 있다. 가능하면 URL 문자열보다 이미지 자체의 안정적인 식별자 또는 해시를 활용해 중복 검수를 줄인다.

## 5. SDVX 난이도 구조 처리 규칙

운영 기획상 난이도 UI는 다음처럼 본다.

- 기본 축: `NOV → ADV → EXH`
- 그 이후 상위/번외 자켓 슬롯은 곡이 실제로 가진 variant를 표시한다.
- 대표적으로 `MXM`, `GRV`, `HVN`, `VVD`, `XCD` 등이 올 수 있다.
- 일반적으로 `MXM`과 `GRV/HVN/VVD/XCD` 같은 번외 패턴이 한 곡에 동시에 존재하는 구조로 가정하지 않는다.
- **예외: `Everlasting Message`는 별도 예외 케이스로 취급한다.**
- 구현에서는 고정 칼럼을 억지로 만들지 않고 실제 `variants` 배열을 source of truth로 삼는다.
- 향후 데이터에서 다른 예외가 확인되면 실제 데이터가 기획 가정보다 우선한다.

권장 데이터 형태:

```ts
variants: [
  { difficulty: "NOV", category: "□" },
  { difficulty: "ADV", category: "□" },
  { difficulty: "EXH", category: "○" },
  { difficulty: "GRV", category: "●" },
]
```

존재하지 않는 `MXM/GRV/HVN/...` 슬롯을 미리 생성하지 않는다.

## 6. 검열 UI에 사용하는 방식

분류값은 향후 공개 사이트의 표시 옵션에 사용한다.

예시:

- 검열 없음 → `● / ○ / □ / ■` 모두 그대로 표시
- 민감 이미지만 가리기 → `●` 블러/숨김
- 강한 검열 → `● + ○` 블러/숨김
- `□ / ■`는 기본 표시

블러된 이미지에는 사용자가 직접 해제할 수 있는 UI를 둘 수 있다.

## 7. 인기순과 완전 분리

민감도 분류값은 인기순 점수에 사용하지 않는다.

즉:

```text
category = 공개 민감도
popularity = 인기 정렬
```

두 값은 서로 독립적이다.

레이시스와 그레이스는 SOUND VOLTEX 대표 인기 캐릭터로서 **인기순에서 상단 우선순위를 부여할 수 있지만**, 해당 캐릭터가 등장한다는 이유만으로 자켓의 `category`가 높아지지는 않는다.

예:

```text
레이시스 일반 자켓
category = □
popularityPriority = 높음
```

## 8. 구현 시 제거/변경할 기존 개념

기존 Draft 구현의 아래 개념은 이 기획과 맞지 않으므로 최종 구현 전에 제거 또는 교체한다.

- `성인 캐릭터 = ●`
- `미성년 캐릭터 = ○`
- `연령 미상 = □`
- `adultScore`
- 캐릭터 연령/설정을 기반으로 한 category 자동 판정

살릴 수 있는 부분:

- variant 단위 category 저장 구조
- 난이도 전환 시 해당 variant의 category를 함께 바꾸는 UI/데이터 흐름
- `● / ○ / □ / ■` 필터 UI 자체

## 9. 전수 검수 원칙

- 실제 자켓 이미지를 보고 판정한다.
- 캐릭터 이름만 보고 추정하지 않는다.
- 난이도별로 이미지가 다르면 각각 확인한다.
- 같은 이미지가 재사용된 경우 중복 판정을 줄인다.
- 애매한 `●`은 `○`로 낮춘다.
- 애매한 `□`는 공개 안전성을 위해 `○`로 올릴 수 있다.
- 검수 결과는 나중에 수정 가능하도록 수동 override 가능한 형태로 유지한다.
